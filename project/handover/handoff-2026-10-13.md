## 6. Architecture as built

**Pipeline:** A70 (USB) → `script/wbcapture.sh` started by launchd → per photo: `imagesnap` opens the camera, takes one photo, closes it → JPEG into the Nextcloud capture folder → Nextcloud syncs → Claude reads.

| Line # | Part | Behaviour |
|---|---|---|
| 1 | Capture folder | `status.txt` (`OK` / `CAMERA_NOT_FOUND` / `CAPTURE_FAILED` / `STOPPED` + time), `latest/latest.jpg` (1 file), `hourly/` (keep 12), `daily/` (keep 7), `capture.request` (agent trigger) |
| 2 | Interval | Every **20 s** (`WBC_LIVE_INTERVAL`), or immediately when `capture.request` exists |
| 3 | Per photo | `imagesnap -l` (list only) → `imagesnap -q -w 1 -d J1455 /tmp/wbcapture-frame.jpg`, with a time limit → copy and atomic rename to `latest/latest.jpg` → tiers → prune → `status.txt` |
| 4 | On failure | The real imagesnap error is logged (harmless `objc … not linked` warning filtered), status becomes `CAPTURE_FAILED`, then it waits **30 s** (`WBC_FAIL_RETRY`) |
| 5 | Safety | imagesnap is killed after **20 s** (`WBC_CAPTURE_TIMEOUT`). A single-instance lock in `/tmp/wbcapture.lock` blocks a second copy. A stop signal (TERM/INT) cleans up and writes `STOPPED` |
| 6 | Service | launchd agent: `RunAtLoad`, `KeepAlive`, PATH includes `/opt/homebrew/bin`, log to `~/Library/Logs/whiteboard-capture.log` |
| 7 | Config | `WBC_DIR`, `WBC_CAMERA` (J1455), `WBC_LIVE_INTERVAL` (20), `WBC_POLL` (1), `WBC_CAMERA_RETRY` (5), `WBC_FAIL_RETRY` (30), `WBC_CAPTURE_TIMEOUT` (20), `WBC_KEEP_HOURLY`/`DAILY` (12/7), `WBC_WARMUP` (1), `WBC_TMP` (/tmp), `WBC_LOCK_WAIT` (30) |
| 8 | Install | `bash project/setup/install.sh` (uses the Nextcloud default). Remove with `bash project/setup/uninstall.sh` |

## 10. Diagnosis

### 10a. Facts

| Line # | Fact |
|---|---|
| 1 | After a **power-cycle** the A70 delivers **one** photo, then fails until the next power-cycle (seen at 18:16, 19:06 (circumstances unclear) and 20:50) |
| 2 | Failures happen from Terminal as well as launchd: **launchd and permissions are not the cause** |
| 3 | The FaceTime camera works with the same imagesnap command: **imagesnap and macOS work in general** |
| 4 | Ruled out: warm-up (1/3/5/8 s), temp file name, Nextcloud folder, double runs, leftover processes |
| 5 | QuickTime and Photo Booth show the A70's **live video** fine. While QuickTime shows it, it holds the camera exclusively |
| 6 | imagesnap 0.3 is a **Swift rewrite from January 2026**. Per photo it opens an `AVCaptureSession` with preset `.photo`, uses Apple's **photo function** (`AVCapturePhotoOutput`), and closes the session again. The old 0.2.x used `AVCaptureStillImageOutput` |
| 7 | Error types: "Capture error: The operation could not be completed" = the camera returned an error; only "Failed to capture photo." = no answer within imagesnap's own **10 s** limit |
| 8 | `imagesnap -l` uses only device discovery and doesn't open the camera |
| 9 | Reports exist of cheap USB cameras on **macOS 26** advertising modes they can't deliver and getting stuck until they're replugged |

### 10b. Hypotheses (not proven)

| Line # | Hypothesis | Fits |
|---|---|---|
| 1 | **Main:** the A70 gets stuck from being **opened and closed repeatedly** (the per-photo design of ADR-0002) | "One photo per power-cycle" |
| 2 | **Alternative:** the A70 can't serve the **photo function** (preset `.photo`, highest mode) reliably, only its video stream | QuickTime and Photo Booth work |
| 3 | **Either way:** open the camera **once** and grab frames from the running **video stream** | Fixes both |
