# Handoff: Whiteboard Capture Setup

**Date:** 2026-10-12  **Owner:** Nils  **Status:** Concept chosen, hardware tested, software designed (not built)

---

## 1. Goal

Capture the current state of a **120 × 90 cm whiteboard** so an agent can read, summarize and work with it during and between whiteboard sessions (brainstorming, structuring, conceptualizing).

## 2. Requirements

| Line # | Type | Requirement |
|---|---|---|
| 1 | Hard | Images must end up in **Nextcloud, Google Drive, a network drive or similar**. The route (camera push, host pull, detour) is open |
| 2 | Hard | **Budget max €60**, tolerance up to **€80**. Above €80 is cut |
| 3 | Hard | Deliverable to **Denmark or Germany** (family in Germany can forward) |
| 4 | Hard | Power via **USB, PoE or battery** |
| 5 | Near-hard | **Wi-Fi**. A PoE-only camera is acceptable if everything else fits |
| 6 | Preference | Delivery directly to Denmark. Common stores (Amazon, Proshop), ideally Danish or German providers |
| 7 | Preference | No vendor cloud lock-in |
| 8 | Open | Images vs. video, trigger (interval / on demand / other), push vs. pull |
| 9 | Given | Distance to board is flexible, **0-2.5 m**. A wall mount with an arm above the board is possible |

## 3. Concepts Evaluated

| Line # | Concept | Example | Est. cost | Verdict |
|---|---|---|---|---|
| 1 | **A. Host + existing USB camera** | MacBook or Pi Zero 2 W + APEMAN A70 / Logitech 1080p | **€0-30** | ✅ **Chosen** (with A70) |
| 2 | B. Pi + CSI camera | Pi Zero 2 W + Camera Module 3 (12 MP, autofocus) | ~€55-60 | ✅ Best image quality, upgrade path |
| 3 | C. DIY microcontroller cam | ESP32-S3 + OV5640 (5 MP) | ~€15-30 | ✅ Cheap, more firmware work |
| 4 | D. Consumer Wi-Fi cam | Tapo C250 (4K, 88° horizontal view) | ~€37 | ✅ RTSP only, needs a host to grab frames |
| 5 | E. PoE IP cam | Reolink RLC-510A (5 MP, FTP + HTTP snapshot) | ~€60-87 + PoE injector | ⚠️ Edge of budget |
| 6 | F. Spare iPhone | iPhone 8/X/11 + IP camera app (RTSP/HTTP) | €0-10 | ✅ App must stay in foreground |
| 7 | G. A70 via Wi-Fi API | Novatek HTTP API over the camera's own hotspot | €0 | 🧪 Hotspot-only, fragile |
| 8 | ESP32 classic + USB webcam | Spare ESP32 | – | ❌ No USB host |
| 9 | Blink | – | – | ❌ Cloud-only |
| 10 | Dedicated whiteboard cams (e.g. Logitech Scribe) | – | – | ❌ Far above budget |

## 4. Key Technical Findings

| Line # | Topic | Finding |
|---|---|---|
| 1 | ESP32 classic | No USB host, so it can't drive a USB webcam |
| 2 | ESP32-S2/S3 | USB host is **full-speed only (12 Mbit/s)**, which gives low resolution or fps from USB cams |
| 3 | ESP32-P4 | The only ESP with **high-speed USB 2.0** host + MIPI-CSI. Wi-Fi comes from a companion ESP32-C6 chip |
| 4 | Raspberry Pi Pico | Too little RAM, no practical webcam support |
| 5 | Tapo | No HTTP snapshot URL, so frames are grabbed from RTSP (e.g. with ffmpeg) |
| 6 | Reolink | E1 and E1 Pro 4MP **lack FTP**. All PoE models support FTP and HTTP snapshots |
| 7 | iPhone vs. Android | Both work. iOS apps must stay in the foreground, and the Lite app edition watermarks frames |
| 8 | Readability | Rule of thumb: ≥1 px/mm on the board. Match the distance to the field of view |
| 9 | Mini-PC alternatives | Radxa Zero 3W, Orange Pi Zero 2W / Zero 3 (Ethernet), Pi 3A+, Luckfox Pico Ultra W, Milk-V Duo S. Pi Zero 2 W has the best software support |

## 5. APEMAN A70 Test Results (chosen camera)

| Line # | Test | Result |
|---|---|---|
| 1 | Chipset | **Novatek** (shows as "NOVATEK J1455" on the Mac) |
| 2 | USB power | Runs on USB in capture mode, even **without a battery** |
| 3 | USB modes | Menu offers **Mass Storage** or **PC Camera** |
| 4 | PC camera mode | Works as a standard webcam on the Mac: **1920×1080 at 20 fps** |
| 5 | Wi-Fi | **Own hotspot only**, no option to join an existing network |
| 6 | Other features | Micro-HDMI out, cyclic recording (3/5/10 min), timelapse (1-60 s) |
| 7 | Readability at 1.5 m | Normal text OK, small text marginal, board fills ~55% of width |
| 8 | Readability at **1.0 m** | ✅ Normal and small text readable, board fills ~70% of width |
| 9 | Fisheye | Moderate, stronger at the corners, correctable in software |
| 10 | Exposure | Dim with a yellow cast, caused by the bright **doorway** in frame. Fix: angle or lamp |

## 6. Chosen Direction

- **I. Hardware:** A70 on an **arm above the whiteboard, ~1 m distance**, USB to the **MacBook** (or Terox), in PC camera mode. Cost **€0**.
- **II. Sessions:** whiteboard sessions run on the MacBook in the Claude app.
- **III. Fallback:** a Pi Zero 2 W (~€30) as an always-on host if the MacBook isn't always available.
- **IV. Upgrade path:** concept B (Pi Camera Module 3) if better image quality is needed.

## 7. Software Design (not yet built)

**Pipeline:** A70 (USB) → capture script (`imagesnap`) → folder on the Mac → (sync) Nextcloud → agent reads.

| Line # | Component | Design |
|---|---|---|
| 1 | Service | macOS **launchd** agent, starts at login, always running |
| 2 | Camera check | Every few seconds, checks if the A70 is present as a camera. If not (unplugged, off, mass storage mode), it idles and retries |
| 3 | Status file | Writes e.g. `OK 16:31` or `camera not found`, so the agent reads this first |
| 4 | Live tier | `latest.jpg` overwritten every **10 s** while the camera is present |
| 5 | Hourly tier | First frame of each hour, keep the **last 12** |
| 6 | Daily tier | First frame of each day, keep the **last 7** |
| 7 | Retention | Pruned automatically after each save, so max ~20 files (GFS-style tiered retention) |
| 8 | Trigger file | Agent writes `capture.request`, script takes a fresh frame within ~1-2 s, then deletes the request |
| 9 | Session mode (optional) | `session.on` file means interval captures (e.g. only on change) until it is removed |
| 10 | Staleness | Agent flags any image older than ~1 min |
| 11 | Image cleanup (optional) | Fisheye/perspective correction and white balance (OpenCV), only if accuracy suffers |

**Nextcloud notes:** Nextcloud creates a new file version **at most every 2 minutes** and prunes versions automatically. Syncing `latest.jpg` every 10 s costs ~100 MB/hour of upload during sessions, which is acceptable on a LAN. Keeping the live tier local is optional.

**Effort:** script ~15 min (to write), setup ~15-20 min (install `imagesnap` via Homebrew, load the service, grant camera permission once), test ~5 min.

## 8. Agent Integration Options

| Line # | Option | Needs | Note |
|---|---|---|---|
| 1 | **Folder + trigger file** (planned) | Capture folder connected to the Claude desktop app | No shell needed. Agent reads files and writes trigger files |
| 2 | Local MCP tool + custom skill | Small MCP server on the Mac exposing `capture_whiteboard` | Most robust 0-click, ~1-2 h |
| 3 | Skill + local shell | Agent with a shell on the Mac (e.g. Claude Code) | Agent runs `imagesnap` directly |

The current Claude app session has file access and computer use on the Mac, but **no shell**. That's why option 1 is planned.
